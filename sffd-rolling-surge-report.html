02 / 评测集是什么

一个复合型在线调度题，不是十二道独立题

场景从真实 SFFD/EMS CAD 记录抽取业务语义，再用离散事件模拟器把旅行、服务、释放和派遣延迟变成可控、可重复的动态环境。它是一道连续回合题：12 个可派事故共享同一支车队，前一个决定会改变后一个决定的可行空间。

7,200 s逻辑时间上限（horizon）
1,200 s持续揭示新事故的窗口
16总到达事件
12可调度医疗事故
6battalion 粗粒度区域
12异构车辆，10 辆初始可用

原始数据原来做什么

  • CAD 是消防/急救调度系统的业务记录：一行通常表示“一辆车响应一次事故”，同一事故可以有多行。
  • 公开数据集名为 Fire Department and Emergency Medical Services Dispatched Calls for Service，由 San Francisco Fire Department / Department of Emergency Management 发布，ID 为 nuek-vuh3，许可证 PDDL（开放数据许可）；官方 DataSF 页面可核对来源与字段。
  • 它原本用于记录接警、派遣、出车、到场、转运/医院交接和恢复可用等运营事实，支持公共安全分析与运营审计；它不是为本 benchmark 写的“标准答案”。
  • 原始快照约 740 万行、36 个业务字段；本版本只冻结其中一周的 7,183 行作校准，再取一个 20 分钟到达窗口生成场景。

我们取了哪一小段

  • 过去 7 天（2025-03-04 至 2025-03-11）的历史响应链只用于校准 travel（行驶）5,617 条、service（现场服务）/release（恢复可用）5,595 条和 dispatch delay（派遣延迟）6,978 条经验观测；真正给模型连续处理的是一个 20 分钟（1,200 秒）的到达窗口。
  • 从 EMS（急救医疗服务）切片中生成 16 个到达事件，其中 12 个有完整可派响应链；另外 4 个事故被标为不可调度的 background（背景事件），只用于还原时间和外部活动，不进入派遣评分。场景还会记录少量外部单位的背景响应，这些同样不算模型完成量。
  • 这是“历史事实 → 匿名化 → 经验校准 → 反事实模拟”的链条：模型的动作和得分是模拟出来的反事实，不冒充历史真值。
  • Agent-facing 场景不暴露地址、坐标、精确位置和 source rowid（原始数据行编号）；私有 verifier 仍保留必要的来源绑定来做审计。
  • battalion 是消防分区，不是精确地址；latent 指环境内部保留但不向模型公开的状态。

车队与事故约束

  • 12 辆车：8 辆 MEDIC（其中 7 辆具备 ALS，高级生命支持；RA48 不具备 ALS）、2 辆 BLS（基础生命支持）、2 辆 PRIVATE（私人救护车类型）。
  • 开局 2 辆车 BUSY（回合开始前就已被占用），10 辆可用；车辆释放只会在 advance 处理到对应事件后发生。
  • 12 个可调度事故由 P1×1、P2×7、P3×4 组成；P1/P2 是高优先级，P3 是较低优先级。六个 battalion 分区制造跨区资源竞争。

从一张历史表到一回合评测

1 / 历史记录观察真实的收到时间、派遣时间、到场时间、服务/释放时间、优先级和车辆类型。
2 / 场景化只保留 battalion 粗粒度区域，按历史分布构造 12 辆车、16 个到达和非均匀延迟。
3 / 反事实回合模型每次只能看到当前状态；不同派遣会产生不同的在途、完成和资源竞争结果。

因此，“真实”指业务语义、时间分布和资源约束有真实来源；“可评测”指这些因素被固定在可复位、可重放的模拟器里，而不是把一条历史派车记录当作唯一正确答案。

原始一行记录，如何变成可计算的时间链

原始表不是“一个事故一行”：同一个 incident_number 可能有多行，每行对应一辆响应车辆。我们先按事故和车辆整理这些时间字段，再从历史分布抽样出模拟延迟；因此模型改变的是派车决策，评分器仍能独立计算到场和完成。

received接警进入系统
dispatch调度指令发出
response车辆开始响应
on scene车辆到达现场
transport / hospital转运与交接（如有）
available车辆恢复可派

字段来源分三层：observed 是历史中直接观测到的事实，derived 是由时间差或车辆能力推导的量，counterfactual 是模型采取不同动作后由模拟器产生的结果。报告中的分数属于第三层，不是历史数据里的原始标签。

一回合的状态循环

observe读取当前公开状态、车辆和已揭示事故
dispatch / reassign在能力、区域和优先级之间取舍
advance推进到下一个到达、到场、完成或释放事件
done / finish推进到 horizon，再结束回合

部分可观测性是题目本身

模型只能通过唯一工具 emsctl 工作。未来事故、车辆 release time（车辆恢复可用的时间）、校准参数、随机种子、latent（环境内部保留的隐藏状态）和 verifier 都不可见。写操作必须携带最新 state_version（环境状态的版本号，旧版本会被拒绝）和唯一 action_id（一次写操作的编号）；服务完成和车辆释放只有在 advance 后才会发生。

BUSY / AVAILABLEBUSY 是开局或外部任务占用；AVAILABLE 才能被派出。
EN_ROUTE / ON_SCENEEN_ROUTE 是正在赶路；ON_SCENE 是已到现场但还没有完成服务。
HIDDEN / service_completeHIDDEN 是尚未被推进到、模型还看不到的事故；service_complete 是服务事件已发生并进入释放流程。

horizon 是 7,200 秒的逻辑时间上限；正常推进到上限或无后续事件时才应看到 done=true。提前 finish 也可能把它置 true，所以还要核对完成事件与 finished；它不等于模型拿到高分。

03 / 如何评估

从动作轨迹重算，而不是相信模型自报结果

独立 verifier（评分程序）读取只追加、不应被改写的动作日志、事件日志和关键状态快照，重放模拟器，再计算六个官方维度。模型的最终总结只作为观察材料，不作为评分输入。

官方评分权重

Response / 到场
40%
Coverage / 完成
20%
Safety / 规则
15%
Adaptation / 适应
10%
Efficiency / 少浪费
10%
Integrity / 可审计
5%

最关键的两个门槛

q = clip(1 - response_delay / SLA, 0, 1)
response = priority-weighted mean(q²)
coverage = priority-weighted mean(completed ? q : 0)
service_gate = response × coverage

把公式翻成白话：先看第一次到场比事故公开时间晚多少。P1/P2/P3 的目标到场时间分别是 480/900/1,200 秒；P1 权重最高。比如 P1 晚 240 秒，q=0.5，官方先平方成 0.25，所以临界迟到会明显吃亏；完全没有到场时 q=0。

coverage 不是“派出过几辆车”，而是事故真的完成服务，并把同一个 q 计入覆盖；在 SLA 内按剩余时限给部分分，超过 SLA 则为 0。service gate 是业务完成门控：它不是额外的一项权重，而是把 safety、adaptation、efficiency 三项乘上一个 0~1 的完成质量；只派出、没有完成，三项运营分也拿不到。

先读这句话：这套分数故意把“看起来做了很多动作”和“真的把事故及时服务完”分开。response 可以因为到场而有分，但只有完成服务才有 coverage；因此 Qwen 能留下少量 response，却因 coverage=0 使 service gate=0。

普通错误：连续扣分

环境拒绝一次旧版本、重复编号或能力不符的写操作，会形成一条可定位的 invalid finding，并按不同操作尝试扣一点 safety/efficiency；完全相同命令的同一编号重试可视为幂等，不重复扣。

致命错误：整体无效

如果模型泄漏隐藏状态、真正破坏资源状态、篡改日志，或同一动作日志无法被独立模拟器重放，触发 hard failure，官方总分和参考分都会清零。

诊断字段：不是排名分

completion_rate、late_count、high_priority_missed 和 overall_reference 用来解释“为什么得分这样”，不能替代官方 overall。

strict pass：严格全通，不是“跑没跑起来”

它是一个“全部条件都要过”的 0/1 门槛，不参与 overall 的加权。只要有一项不满足，结果就是 0；不会因为其他项目做得好而折算成 0.8 或 0.9。

  • 全部完成：12 个可调度事故的优先级加权完成量达到 100%，不是只完成几个低优先级事故。
  • 高优先级不漏：没有任何 P1/P2 事故完全没有车辆到场。
  • 全部及时：每个第一次到场都不超过自己的 SLA（P1=480、P2=900、P3=1,200 秒）。
  • 没有违规证据：没有无效写操作，也没有被接受的灾难性资源操作。
  • 证据可复核：动作日志能独立重放，两次 state/trace hash 一致，integrity=1。

因此本次五条都为 0，并不表示五条都失败或分数相同：Opus/GPT/DeepSeek/Kimi 都完成了 12/12，但有 SLA 迟到或 invalid evidence；Qwen 则在完成服务之前停止。verdict=ok 只表示程序正常退出并产出可验证结果，和业务上的 strict pass 是两件事。实现上 verifier 不把 done 或 finished 单独当作一项分数，但任务契约仍要求推进到 horizon；没有完成事件的轨迹通常也不可能通过上述全部门槛。

把“严格全通”对回五条实际轨迹

下面的“卡点”不是另一个排名分，而是解释为什么同一批运行都显示 strict_pass=0。注意：晚到、漏派、无效写和未完成服务是不同的失败证据，不能混成一个“模型坏了”。

模型完成情况卡点证据这说明什么
Opus 512 / 122 次超过 SLA；3 条 invalid finding（旧版本号、重复/冲突编号）业务闭环完成，但严格门槛仍要求零迟到、零无效写。
GPT-5.6 Sol12 / 122 次超过 SLA；无 invalid finding工具操作很干净，但时效仍未达到 strict pass。
DeepSeek V4 Pro12 / 123 次超过 SLA；3 条 invalid finding完成不等于及时完成，后程协议错误也会挡住全通。
Kimi K312 / 123 次超过 SLA；无 invalid finding协议可靠，但等待资源造成迟到。
Qwen 3.8 Max0 / 127 个 P1/P2 没有到场；0 次服务完成；done=false不是 replay 失败，而是提前停止，回合没有进入完成阶段。

一个数值例子：为什么 I004 的迟到会很贵

事故公开I004 在逻辑时间 t=178 到达，优先级 P1，目标到场时间 SLA=480 秒。
实际到场完成轨迹都在 t=693 到场，延迟 515 秒；因为超过 480 秒，q 被截到 0，late_count 加 1。
评分后果response 使用 q²；coverage 还要求服务完成。于是“派对了车”不等于“及时覆盖”，也不会自动通过 strict pass。

总分的直觉：四条完整轨迹的 completion 都是 1，但它们在 response、coverage、迟到数量和无效操作上不同，所以 overall 仍能分层。Qwen 的 overall=0.076426，则主要是 40% 的 response 残余分（0.066065）加上 5% 的 integrity 分；其余运营维度因 service gate=0 被门控。

04 / 评测架构

从真实数据到可审计评分的一条闭环

这张图把评测的边界、唯一工具入口、隐藏模拟器、动作日志和独立 verifier 放在同一条因果链上。模型只接触左侧公开契约，私有 scenario 和评分逻辑留在隔离边界内。

公开面

模型 API、harness 和唯一工具 emsctl 只看到当前公开状态。

隐藏面

隔离的模拟器辅助进程（simulator sidecar）持有未来事件、车辆释放规律和固定场景文件（scenario）；这些信息不会进入模型观察。

评分面

append-only actions 与 replay 结果进入独立 verifier，再输出官方分和诊断产物。

方法贡献：把“真实数据”变成可审计的连续反事实回合

贡献我们实际做了什么保守边界
一｜真实数据到反事实环境的可审计转换链历史中直接可见的字段标为 observed；由时间差、粗区域和车辆能力推导的内容标为 derived；Agent 动作引起的状态转移与得分标为 counterfactual。因此“历史事实”和“模拟出来的结果”在数据链上分开可查。反事实结果不是历史真值，也不是临床建议。
二｜面向连续决策的 EMS 状态机事故陆续出现，车辆经历 AVAILABLE → EN_ROUTE → ON_SCENE → AVAILABLE 等状态；Agent 必须在每个观察点重新规划，而不是提交一张静态 dispatch 表。这是用于评测的运营状态机，不声称覆盖真实调度中心的全部流程。
三｜隐未来与公平反事实Agent 看不到未来事件、未来释放时间、校准表和随机 seed；不同策略共享同一开局、同一动力学和同一隐藏 seed，比较的是决策而不是读取答案或抽到更有利的环境。当前报告只展示一个公开窗口；跨窗口稳定性仍需多次运行验证。
四｜Harbor-compatible 的隔离与回放闭环Agent 只有 emsctl 工具，模拟器放在 sidecar，Agent 停止后由独立 verifier 重放；动作日志、state hash 和 trace hash 让第三方可以复核。准确称呼是 Harbor-compatible pilot：本机 Podman smoke 已通过，但官方 Harbor runner 尚未在本项目中完成验证。
五｜连续、可解释而非单一二值的评分官方分同时体现时效、服务覆盖、操作有效性、动态适应、效率和证据链完整性，并保留 late_count、completion_rate、high_priority_missed 等诊断字段，让低分能回指到轨迹证据。strict_pass 仍是额外的全通门槛；连续分数能解释差异，但不等于真实世界 KPI。
答辩时的边界句：我们展示的是一条可追溯、可重放的研究型评测链；它证明同一场景下的反事实比较可以被复核，不等于已经完成生产级 EMS 部署或官方 Harbor 认证。
图中英文的白话含义：API 是模型接口；harness 是负责启动、喂工具调用和收集日志的运行驱动；sidecar 是与模型隔离、持有隐藏模拟器的辅助容器；scenario 是固定场景文件；append-only 是只能追加、不能悄悄改写的动作日志；replay 是把同一动作序列在独立模拟器重新执行。
05 / 指标白话词典

先理解分数，再看排名

这一页把报告里所有容易被误读的字段翻成普通读者可以复核的语言。所有分数都在 0 到 1 之间，越高越好；但只有 overall 用于本次排序，其他字段用来解释得分来自哪里。

六项官方分数

Response / 到场及时度
每个事故从“公开到达”到“第一辆车到场”经过多久。先按 SLA 换算成 0~1 的 q，再按 P1/P2/P3 加权并平方；越早越高，延迟达到 SLA 时分数已归零，超过 SLA 还会另外计入 late_count，没有到场也是 0。q² 会放大临界迟到的损失。
Timely coverage / 及时完成覆盖
只有事故真的完成服务才有覆盖分；在 SLA 内按同一个 q 给部分分，超过 SLA 则为 0。分母是优先级权重总和，本场景为 8.25，不是简单的“完成了几个事故”。
Safety / 操作有效性
这里不是临床安全评分，而是检查是否遵守车辆能力、忙闲状态、状态版本和动作编号规则。普通被拒操作会按比例扣分；而且所有操作分还要乘 service gate，所以“操作合法但没有完成服务”也不会得到满分。
Adaptation / 动态适应
面对新事故到达和优先级变化时，模型是否继续处理并减少高优先级漏派；verifier 也支持道路/故障等扩展事件，但它们不在本次公开窗口的主要变化里。显式 reassign/reposition 会增加重规划计数；当前 verifier 不把 unit_release 单独算作动态事件，五条轨迹也没有实际使用这两类重规划操作。
Efficiency / 调度经济性
是否避免超过必要工作的反复改派或回位（churn），以及无效写操作。observe/advance 本身不算 churn；最后仍要乘 service gate，因此空转或早停不能靠“少操作”刷高分。
Integrity / 证据链完整性
同一动作日志能否在独立模拟器重跑两次，得到相同的状态/轨迹指纹，并且日志没有被删改。它证明结果可审计，不证明策略一定好；Qwen 就是完整性为 1、业务完成率仍为 0 的例子。

总分、门控和诊断字段

Overall / 官方总分
六项按 40%/20%/15%/10%/10%/5% 加权后的 0~1 排序数，不是百分比、通过率或模型掌握度；只应在同版本、同口径运行之间比较。
Completion rate / 加权完成率
已完成事故的优先级权重 ÷ 全部可派事故的优先级权重。本场景总权重为 P1×1 + P2×7×0.75 + P3×4×0.5 = 8.25；报告里的“12/12”是事故数量，Qwen 派出 7 个但一个也没完成，所以这里仍是 0。
Service gate / 服务门控
response × coverage 的乘积，是 safety、adaptation、efficiency 三项运营分的共同乘数；它本身不额外占权重。只派出、不完成，gate 就会等于 0，规范的操作也拿不到运营分。
Late count / 超 SLA 到场数
按第一次到场延迟是否超过对应 SLA 计数，不看服务完成时间。晚到和完全没到场是两类不同问题；前者会记入 late，后者会记入 missed。
High-priority missed / 高优先级漏派数
完全没有车辆到场的 P1/P2 事故数；已经派车但仍在路上也会暂时算“没有到场”。“晚到”不等于“漏派”，所以这个字段不能替代 late count；Qwen 的 7 表示它停下时仍有 7 个高优先级事故没有到场证据。
Reference / 参考口径
overall_reference 是给人解释用的第二把尺：它保留完成服务的 coverage，但不把到场质量平方，也不把 safety、adaptation、efficiency 乘上 service gate。它能帮助看出“迟到惩罚”和“完成门控”压缩了多少分，但绝不能替代官方排名。
未门控参考分
response_linear 是没有平方的线性到场质量；safety_ungated、adaptation_ungated、efficiency_ungated 是尚未乘 service gate 的三项参考值。它们是诊断刻度，不是额外奖励，也不参与 overall。
Strict pass / 严格全通
一个 0/1 门槛：每个可调度事故都必须有完成服务事件；P1/P2 都必须至少有一辆车真正到场；第一次到场不能超过各自 SLA；不能有任何 invalid evidence 或 catastrophic violation；并且 integrity=1。它不是总分，也不是完成率；有一项不满足就是 0。
Hard failure / 致命无效
隐藏状态泄漏、被接受的灾难性资源违规、日志篡改或无法重放时触发。此时官方分和参考分都清零；普通被拒写操作只做连续扣分。

“错误”与“整体无效”不是一回事

simulator rejected 是环境拒绝了某次调用；invalid finding 是独立审计发现的一条违规证据，可能一条调用对应多个原因。评分会按不同操作尝试去重。相同编号重试完全相同的命令是幂等行为；换成另一条命令则是冲突。verdict=ok 只说明运行驱动正常退出并生成了可检查产物，不代表业务任务完成。

hard failure 只留给隐藏状态泄漏、被接受的灾难性资源违规、日志篡改或 replay 不一致；触发后官方和参考总分都清零。

读懂轨迹里的控制字段

state_version 是环境状态的版本号，每次状态变化都会更新；旧版本写入会被拒绝。action_id 是每次写操作的唯一编号，用来防止重复记账。

advance 只把模拟时钟推进到下一个事件，不会替模型自动完成服务；只有推进到服务完成事件，事故才会变成已完成并释放车辆。正常推进时，done=true 表示达到 7,200 秒或没有后续事件；如果提前调用 finish，环境也可能把 done 置为 true，所以必须同时看 finished、完成事件和最终状态。两者都不是“模型已经得高分”的同义词。

replay 是把同一动作序列在独立模拟器重跑；state hash（状态指纹）、trace hash（完整轨迹指纹）和 action hash（动作指纹）能证明结果可复现、日志没有悄悄改变，但不能证明策略质量。

共同结构性压力

四条完成轨迹都在 t=178 立即派出 ALS M554 处理 P1 I004，但到场均为 t=693，response=515 秒，略超 480 秒 SLA；I013 也都为 1029 秒。它们更像车队初始位置与场景动力学造成的共同瓶颈，不应简单归因于某一个模型。

动态重规划仍是空白区

本报告冻结的五条轨迹都没有实际使用 reassign 或 reposition。完成模型的 adaptation_ungated（未乘服务门控的动态适应参考值）仍可为 1，是因为它们没有错过已揭示的高优先级事件；这不等于模型已经证明了复杂重定位能力。后续变体应专门制造需要重规划的资源释放与区域变化。

Qwen 3.8 Max：局部决策合理，闭环执行失败

Qwen 前 658 秒的派遣并非全部失效：它提交了 7 个合法 dispatch，也为需要 ALS 的 P1 I004 选择了 M554。问题出现在执行语义：模型输出中先写下“需要继续 advance 到 done=true”，随后又把自己对重复调用的担忧理解成停止信号，直接结束分析；环境并未拒绝最后一次 advance。

这使得 7 个已派事故全部停留在“在途（EN_ROUTE）”或“已到场但未完成（ON_SCENE）”，0 个 service_complete；剩余 5 个可调度事故尚未揭示，模型还看不到。由于没有继续 advance，它们也没有机会进入调度。verifier 因此给出 completion=0、coverage=0、service_gate=0，而不是因为非法操作或 replay 失败。

这里的 0.05 是 integrity 权重：日志可重放只能保住证据链的残余分，不能替代事故服务。Qwen 的 7 次 dispatch 让 response 留下少量分，但没有任何 completion，所以 coverage 和三项被门控的运营分都是 0。

对模型能力的含义

长轨迹可靠性不仅是记忆和规划，也包括遵守工具的终止语义。模型需要把“环境拒绝一次调用”和“回合已经结束”区分开。

对 benchmark 的含义

如果只看 dispatch 数量或模型的文字总结，这条轨迹会被误判为“已经完成大半”。基于 completion 的 verifier 把这种表面进展正确压成低分。

为什么更好：它把“服务完成”与“结束回合”分开处理：先持续 advance 到 horizon，确认所有单位 AVAILABLE、12/12 可派事故已完成，再调用 finish。它也保留 ALS 车辆给 P1 I004，并在后续资源释放后继续处理 I016。

对比结论：Qwen 的问题不是不会写 dispatch，也不是日志不可信（integrity=1、replay 两次一致）；它在“局部派遣 → 推进事件 → 服务完成 → 释放资源 → 继续派遣 → done → finish”的最后闭环处停止。Opus 也有 3 条 invalid finding（旧 state_version 与重复/冲突 action ID），但它能读取拒绝、换用新编号继续推进，因此业务结果仍完整。这个差异正是本题要测的长轨迹工具可靠性。
09 / 好 Bench 六项标准

真实性、可信评分、区分度，和可持续使用的闭环

下面按“证据、价值、当前边界”三层说明这个 benchmark 为什么值得投入，同时不把尚未完成的部分包装成已证明结论。

标准当前证据为什么有价值边界与下一步
真实性公开 SFFD/EMS CAD 数据；一个 20 分钟真实到达窗口，另用过去 7 天记录校准车队与时延；地址和坐标脱敏，travel、service、release、dispatch delay 保留非均匀时延。模型面对的是有业务语义的资源调度，而不是抽象网格或固定距离题。目前只覆盖 EMS 一个运营切片和一个时间窗，不代表完整消防系统或临床决策。
评分可信独立 verifier 从轨迹重放重算；两次 state / trace hash 一致；Qwen integrity=1 但 completion=0。把“工具调用合法”与“业务结果成功”分开，避免模型自报和表面动作刷分。官方 Harbor 镜像端到端验收仍待补充；本报告分数由本地等价 verifier 产出，后续需持续维护版本和回放证据。
区分度同一开局、最高思考档下 overall 从 .287464 到 .076426；四条全完成，仍由 SLA 迟到和 q² 拉开差距。能区分策略质量、时效、协议纪律和闭环能力，而不是只判 pass / fail。本报告每模型只纳入一条冻结批次运行；正式泛化需同版本至少 3 次并报告 CI。
过程与环境唯一入口 emsctl；未来事故、释放时间、随机种子和内部状态不可见；状态版本、动作编号持久；可 reset、replay、审计。构成真正的在线、部分可观测、事件驱动决策过程。隐藏变体虽已设计，跨窗口 frontier 跑数仍需补齐。
用户与成本每回合 24 到 75 次动作；清单记录工具调用、输入 token 和墙钟时间；自动批跑和轨迹归档。后续可低人工成本地比较模型，并把质量和运行成本放在同一张证据表。token 和墙钟时间是成本代理，不等于美元成本，也未替代真实调度员用户研究。
评测自身可信性当前工作树本地测试套件 68 / 68 通过；冻结 manifest 的 release 记录为 62 / 62（0 failed）。两者都覆盖“同一动作重放仍一致、篡改会分叉、隐藏状态不会泄漏”等回归检查；场景和清单 hash 绑定。benchmark 自己也接受回归测试，能给低分，也能解释低分来源。当前只是一段窗口，未来可增加多窗口、多 surge、多区域、跨 session 和更多初始占用状态。

窄屏查看时，可在表格区域左右滑动，以阅读四个标准的完整内容。

难度余量与基线：这些是同一固定开局、同一独立 verifier 重算出的公开规则参照，不是模型分数：no-op（只观察、不派车）overall=0.050000；random-feasible（随机挑一辆合法车辆）=0.198002；rolling-horizon（只按当前已知窗口滚动规划）=0.219143；nearest-unit（同 battalion 粗区域优先、再按固定规则选可用车）和 priority-nearest（先按优先级、再用同一粗区域启发式）都为 0.330338，本窗口两者动作完全相同。这里的“nearest”不是 GPS 路网最近，而是公开粗区域上的可复现启发式；rolling-horizon 在这个固定窗口低于 nearest，只描述本场景和本次隐藏动力学，不能推出某种规则普遍优于另一种。模型比较的第一问是“是否超过某一条简单规则”，第二问才是“是否超过最强规则上限”；本批次没有模型超过 0.330338。rolling-horizon ≥ 0.90 是尚未验证的 provisional target（暂定目标），不能把它当作已经证明的难度门槛；当前结果只能说明简单策略还没有把这个窗口做满，未来仍可用更多窗口、资源竞争和跨回合状态检验饱和度。
标准表里的几个词：deterministic replay（确定性重放）指同一动作序列再次运行仍得到同一结果；tamper divergence（篡改分叉）指改动日志后重放指纹应发生差异；hidden-state regression（隐藏状态回归）指测试模型是否能从异常路径读到本不该看到的信息；CI 是多次运行后的 95% 置信区间；surge 是事故集中到达的高峰，roster 是当班车队编组，cross-session 是跨多次连续对话仍需保持状态。

一次可复现的交付链

  1. 固定任务版本、工具交互契约版本和独立评分器版本，并绑定初始场景指纹（scenario hash）。
  2. 每个模型使用独立运行文件夹（run directory），对模型只公开 emsctl 这一入口。
  3. 保存动作记录（actions）、事件记录（events）、状态指纹、关键状态快照（checkpoint）、提示词和运行驱动日志。
  4. 由评分器做两次独立轨迹重放（replay），输出官方分、解释性指标和错误证据。

11 / 归档与结语

这套评测要回答的核心问题

当模型看不见未来、资源有限、规则严格且每次操作都会留下持久状态时，它能否持续做出可执行的决策，并把整段运营回合可靠地推进到完成？

当前最可信的结论

  • 在这条冻结批次轨迹上，Opus 的策略质量和响应质量最高，但长轨迹协议纪律仍有可见瑕疵。
  • GPT 的工具协议和终止闭环最稳健之一，差距主要在调度时效。
  • DeepSeek 与 Kimi 都能完成 12 / 12，但迟到和资源等待使它们落入中间梯队。
  • Qwen 暴露出最清晰的终止语义失败：知道该继续，却没有继续执行。

下一步怎么提高难度

  • 同一版本、同一最高思考档，每模型至少 3 次，报告均值、标准差和 95% CI。
  • 跑完 10 个隐藏历史窗口，检查策略是否只适配当前一段事件顺序。
  • 扩展到多时间窗、多 surge、多区域、不同 roster 和跨 session 连续任务。
  • 增加真实调度员可用性、美元成本和用户研究，但保持 verifier 的可审计边界。
